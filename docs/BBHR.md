# BB HR — staff PWA for Black Building Academy

Vue 3 + TypeScript progressive web app on Frappe HRMS, served by this app at **`/bbhr`**.
Employees check in with GPS + selfie, see attendance, payslips and holidays.
Reporting managers see their team; HR sees the whole company.

## Architecture

| Layer | Where | Notes |
|---|---|---|
| SPA | `frontend/` (Vite, Vue 3, TS, Tailwind, Pinia, Vue Router, lucide icons, @vueuse/motion) | built into `bb_academy_hrms/public/bbhr/` |
| Page | `www/bbhr.html` + `www/bbhr.py` | generated by `frontend/scripts/make-page.mjs`; injects the session CSRF token |
| Service worker | `www/bbhr_sw.js` (served at `/bbhr_sw.js`, scope `/bbhr/`) | generated from `frontend/sw-template.js` |
| API | `bb_academy_hrms/api/*.py` | every endpoint resolves scope server-side via `utils/permissions.py` |
| Settings | DocType **BB HR Settings** (+ child **BB HR Office Location**) | geofence, radius, photo, attendance creation |
| Custom fields | `Employee Checkin.bbhr_*` (office, distance, accuracy, photo, request id) | created by `setup/install.py` on migrate |

### Design system (PWA)
Mobile-first, 480px centred frame (grey outside on desktop). Tokens in `frontend/tailwind.config.js`:
primary `#048EFF` (`brand-500`), pressed `#0277D6`, danger `#E21B22`/`#FDE3E4`, success `#2E9E5B`,
warning `#F2A23A`, avatar yellow `#FFBF48`, text `#212121`, muted `#808080`, surface-alt `#F1F1F1`, border `#E3E3E3`;
cards 12px radius. Shared pieces in `src/components/ui/`: `AppBar` (blue bar, back/hamburger, `extension` slot),
`HeaderTabs`, `BottomNav` (Home · Attendance · + · Salary Slip · Account), `FabActionSheet`, `SideDrawer`,
`StatCard`, `QuickLinkTile`, `StatusBadge` (status chip), `LogTable`, `FilterBar`, `MaskedAmount`, `EmptyState`,
`Skeleton` (shimmer), `AppButton` (primary button). Illustrations are original SVGs: the people scenes in
`public/illustrations/` are generated by `scripts/make_illustrations.py` (`npm run illustrations`), and the
skyline / hand-with-phone are inline components in `src/components/illustrations/` and the logo is `BrandLogo.vue`.
Leave / Expense Claim / Advance / Permission Request screens are not built (no such feature or doctype yet).

### Desk workspaces (Frappe backend, `/app`)
| Workspace | URL | Who | Shows |
|---|---|---|---|
| **BB HR** | `/app/bb-hr` | HR Manager, HR User, System Manager | Present / In now / Late / Not marked / On leave today, staff without login; 30-day attendance chart; department presence today; shortcuts and links |
| **My HR** | `/app/my-hr` | Employee (Desk users) | my status today, present/absent days and hours this month, last net pay, next holiday; my attendance for 6 months; links into the PWA |

Cards are `Number Card` type *Custom* and charts use `Dashboard Chart Source`s, all calling `api/desk.py`, which
checks scope on every call. They intentionally avoid Frappe's `cache_source` (it caches per chart, not per user).
Desk only lists a Custom card when its `document_type` (Attendance) is readable, and a chart when one of its
`roles` matches; the Employee role has read-only access to BB HR Settings so the module (and My HR) is visible.
All records are standard (exported JSON under `bb_academy_hrms/bb_academy_hrms/{workspace,number_card,dashboard_chart,dashboard_chart_source}`)
and are installed by `bench migrate`.

### Roles and scope (enforced in `utils/permissions.py`)

| Who | Detected by | Can see |
|---|---|---|
| Employee | User linked on an **Active** Employee (`user_id`) | own attendance, check-in, payslips, holidays |
| Reporting manager | has employees below them in **Reports To** (direct + indirect) | team attendance, exceptions, directory — **never salary** |
| HR administrator | role **HR Manager**, **HR User** or **System Manager** | everyone, including salary slips |

### Check-in rules (`api/attendance.py`)
- Time is the **server clock**; the client never supplies it.
- Geofence: nearest enabled office; allowed if `distance ≤ radius + min(accuracy, tolerance)`. Fixes worse than *Max Accepted GPS Accuracy* are refused.
- Selfie (if required) must decode as a real JPEG/PNG/WebP ≤ 2 MB; stored as a **private** File on the check-in.
- Duplicates: row lock on the Employee, unique `request_id` (a retry returns the original punch), IN/OUT must alternate, minimum gap between punches (never < 1 s).
- Payroll here is **attendance-based**: with *Create Attendance From Check-ins* on, the first IN of the day creates and submits a *Present* Attendance; each OUT updates in/out time and working hours. Split shifts (several IN/OUT pairs) keep one Attendance per day. If Attendance can't be created (e.g. HR already marked the day), the punch is kept and a warning is shown.
- The UI shows success **only** when the server returns the created check-in. A dropped connection shows "couldn't confirm" and the retry reuses the same `request_id`, so it can never double-punch. Offline, the button is disabled.

### PWA / caching
- Only hashed static build files are cached (precached by the SW). `/api/`, `/private/`, `/files/` and the `/bbhr` pages are never cached; offline navigation shows a built-in "You're offline" page.
- `utils/http.py` (`after_request`) sends `Cache-Control: private, no-store` on all BB HR API responses and pages, so payslips are not kept in browser or proxy caches.
- New versions wait for the user to tap **Update** (no reload mid check-in).

## First-time setup on a site

```bash
cd ~/dreamtech-bench
# schema (DocTypes + Employee Checkin custom fields). Either the full migrate...
bench --site bbacademy-erp.dreamtechsolution.com migrate
# ...or, on a live site, only this app's schema:
bench --site bbacademy-erp.dreamtechsolution.com execute bb_academy_hrms.setup.install.sync

bench build --app bb_academy_hrms        # runs `npm ci` + `npm run build` via package.json
bench --site bbacademy-erp.dreamtechsolution.com clear-cache
sudo supervisorctl signal HUP dreamtech-bench-frappe-web   # graceful; or: kill -HUP <gunicorn master pid>
sudo supervisorctl restart dreamtech-bench-workers:          # background workers pick up new code
```

PDFs: wkhtmltopdf must be able to reach the site. Because this bench has
`webserver_port: 8000` and `restart_supervisor_on_update: false`, Frappe appends `:8000`
to generated URLs. Each site therefore needs an explicit `host_name` with port:

```bash
bench --site <site> set-config host_name "https://<site>:443"
```

### Data HR must set up (Desk)
1. **BB HR Settings** (`/app/bb-hr-settings`): add at least one Office Location with real latitude/longitude
   (right-click the building in Google Maps → copy coordinates) and a radius. Until then every check-in is refused by design.
2. **Employee → User ID**: link each staff member's login. Without it they see "Your login isn't linked".
3. **Employee → Reports To**: build the manager hierarchy so managers get the Team views.
4. Give HR staff the **HR Manager** or **HR User** role.
5. Optional: Shift assignments (used for late-arrival detection; grace from Shift Type "late entry grace period").

## Development

```bash
cd apps/bb_academy_hrms/frontend
npm ci
npm run dev            # http://localhost:8081/bbhr/ , proxies /api to BBHR_BACKEND (default http://localhost:8000)
npm run typecheck
npm test               # vitest: geo/format/api + check-in component behaviour
npm run build          # vue-tsc + vite build + make-page (writes www/bbhr.html, www/bbhr_sw.js)
npm run icons          # regenerate PNG icons with Pillow
```

Note: geolocation and camera need **HTTPS** (or localhost).

Backend integration checks (real site, always rolled back; `commit` is patched to raise):

```bash
bench --site bbacademy-erp.dreamtechsolution.com execute bb_academy_hrms.tests.integration.run
```

## Production deployment checklist
1. `git pull` the app, then `bench build --app bb_academy_hrms` (or commit the built `public/bbhr` + `www/bbhr*` as is done here).
2. `bench --site <site> migrate` (creates/updates DocTypes and custom fields; idempotent).
3. Ensure `host_name` is set with an explicit port (see above) and the site is served over HTTPS.
4. Graceful reload of gunicorn + `clear-cache`.
5. Smoke test: `/bbhr` loads, guest is sent to `/bbhr/login`, an employee sees the dashboard, a payslip PDF downloads.
